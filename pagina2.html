RA1.01Gestión de servidor (hosting) y dominios

Gestión de servidor (hosting) y dominios

La gestión de servidor y dominios agrupa las tareas necesarias para mantener operativo el alojamiento donde vive un sitio web y el nombre mediante el cual los usuarios lo encuentran. Incluye la configuración inicial del entorno de hosting, el monitoreo de disponibilidad, la renovación oportuna del dominio y la coordinación entre ambos servicios para evitar interrupciones. Una gestión deficiente puede dejar un sitio inaccesible aunque el código y el contenido estén completamente correctos. Esta disciplina es la base sobre la que se apoya cualquier estrategia posterior de seguridad, rendimiento o posicionamiento.

Un administrador programa recordatorios de renovación del dominio con dos meses de anticipación para evitar que expire por descuido.

La mayoría de las caídas de sitios web por causas administrativas se deben a dominios vencidos, no a fallas técnicas del servidor.

RA1.02Adquisición de servidor remoto (hosting)

Adquisición de servidor remoto (hosting)

Adquirir un servidor remoto implica elegir entre distintos modelos de hosting —compartido, VPS, dedicado o en la nube— según el tráfico esperado, el presupuesto disponible y el nivel de control técnico requerido. Cada modelo ofrece un balance distinto entre costo, rendimiento y responsabilidad de mantenimiento por parte del cliente. Evaluar correctamente estos factores antes de contratar evita migraciones costosas una vez que el sitio ya está en producción. La decisión también debe considerar la ubicación geográfica del centro de datos, que afecta directamente la velocidad de carga para la audiencia objetivo.

Un proyecto que espera picos de tráfico estacional contrata un servidor en la nube con escalado automático en lugar de un plan compartido fijo.

Un servidor VPS ofrece recursos garantizados mediante virtualización, a diferencia del hosting compartido, donde los recursos se distribuyen entre múltiples clientes.

RA1.03Gestión del dominio

Gestión del dominio

La gestión del dominio cubre el registro, la configuración de registros DNS, la renovación y la transferencia del nombre que identifica a un sitio en internet. Un registro DNS mal configurado puede impedir que el dominio apunte correctamente al servidor o que el correo electrónico asociado funcione. Mantener actualizados los datos de contacto y activar el bloqueo de transferencia son prácticas básicas para evitar el secuestro del dominio. Esta gestión debe revisarse periódicamente, incluso cuando el sitio funciona sin incidentes aparentes.

Un equipo técnico actualiza el registro tipo A de su dominio para apuntar a la nueva dirección IP tras migrar de servidor.

El sistema de nombres de dominio, DNS, funciona como una guía telefónica de internet, traduciendo nombres legibles en direcciones IP numéricas.

RA1.04Manejo de base de datos

Manejo de base de datos

El manejo de base de datos en el mantenimiento de una plataforma web incluye tareas como respaldos periódicos, optimización de consultas, control de accesos y monitoreo del espacio de almacenamiento. Una base de datos descuidada puede volverse el principal cuello de botella de rendimiento incluso cuando el resto del sistema está bien optimizado. Los respaldos automatizados y probados regularmente son la defensa más efectiva frente a pérdida de información por fallas o errores humanos. Documentar la estructura de la base de datos facilita el mantenimiento cuando distintas personas participan en el proyecto a lo largo del tiempo.

Un administrador configura respaldos automáticos diarios de la base de datos y verifica mensualmente que puedan restaurarse correctamente.

Muchas pérdidas de datos no ocurren por fallas técnicas, sino porque los respaldos existentes nunca fueron probados antes de necesitarse.

RA1.05Características de seguridad en la publicación de páginas Web

Características de seguridad en la publicación de páginas Web

La seguridad en la publicación de páginas web abarca medidas como el cifrado de la conexión, la validación de entradas de usuario, el control de permisos y la actualización constante del software utilizado. Publicar contenido sin estas medidas expone el sitio a accesos no autorizados, inyección de código malicioso y filtración de información sensible. La seguridad no es un paso final, sino una práctica que debe integrarse desde el diseño inicial de la plataforma. Ignorar estas características puede comprometer no solo el sitio afectado, sino también la confianza de los usuarios que interactúan con él.

Antes de publicar un formulario de contacto, un desarrollador valida y filtra los datos ingresados para evitar inyecciones de código.

La mayoría de los ataques exitosos a sitios web explotan software desactualizado en lugar de vulnerabilidades desconocidas.

RA1.06Seguridad en distintos sistemas de archivos

Seguridad en distintos sistemas de archivos

Cada sistema de archivos, ya sea en servidores Linux o Windows, maneja de forma distinta los permisos, la encriptación y el registro de actividad, por lo que su seguridad debe configurarse conforme a las particularidades de cada uno. Un sistema de archivos mal asegurado puede permitir que un usuario o proceso acceda a información fuera del alcance que debería tener. Establecer jerarquías claras de carpetas y restringir el acceso según el principio de menor privilegio reduce significativamente el riesgo de exposición. La auditoría periódica de accesos ayuda a detectar comportamientos anómalos antes de que se conviertan en incidentes mayores.

Un servidor Linux configura permisos restringidos en la carpeta de configuración para que solo el usuario administrador pueda modificarla.

El principio de menor privilegio establece que cada usuario o proceso debe tener únicamente el acceso mínimo necesario para cumplir su función.

RA1.07Permisos de acceso

Permisos de acceso

Los permisos de acceso determinan qué usuarios o procesos pueden leer, escribir o ejecutar un archivo o directorio dentro de un servidor. Una asignación incorrecta de permisos, ya sea demasiado restrictiva o demasiado permisiva, puede generar errores de funcionamiento o brechas de seguridad graves. En sistemas tipo Unix, los permisos se representan mediante combinaciones numéricas o simbólicas que definen el nivel de acceso para propietario, grupo y otros usuarios. Revisar periódicamente estos permisos evita que configuraciones temporales de prueba queden activas de forma permanente en producción.

Un archivo de configuración sensible se restringe con permisos que solo permiten lectura y escritura al usuario propietario.

En sistemas Unix, un permiso 777 otorga acceso total a cualquier usuario, por lo que se considera una práctica insegura salvo casos muy puntuales.

Sistemas de archivos y comandos

Administrar un servidor exige conocer la estructura del sistema de archivos utilizado y dominar los comandos básicos para navegar, crear, mover y eliminar elementos dentro de él. Sistemas como ext4 en Linux o NTFS en Windows organizan la información de forma distinta, lo que afecta el rendimiento y las herramientas disponibles para su mantenimiento. El dominio de la línea de comandos permite realizar tareas de administración de forma más rápida y automatizable que mediante interfaces gráficas. Este conocimiento es indispensable para diagnosticar problemas cuando el acceso gráfico al servidor no está disponible.

Un administrador utiliza comandos de terminal para localizar y eliminar archivos temporales que ocupan espacio innecesario en el servidor.

El sistema de archivos ext4, ampliamente usado en servidores Linux, introdujo mejoras significativas de velocidad y confiabilidad frente a sus versiones anteriores.

Órdenes de creación, modificación y borrado

Las órdenes de creación, modificación y borrado permiten gestionar archivos y directorios directamente desde la línea de comandos, una habilidad esencial para el mantenimiento ágil de una plataforma. RA1.10Instalar certificados de seguridad

Instalar certificados de seguridad

Instalar un certificado de seguridad permite cifrar la comunicación entre el servidor y los usuarios mediante el protocolo HTTPS, protegiendo datos sensibles frente a interceptación. El proceso incluye generar una solicitud de firma, obtener el certificado de una autoridad certificadora y configurarlo correctamente en el servidor web utilizado. Un certificado mal instalado o vencido genera advertencias de seguridad en el navegador que reducen drásticamente la confianza del usuario. La renovación automática de certificados se ha vuelto una práctica estándar para evitar interrupciones por vencimiento.

Un administrador configura la renovación automática de su certificado para evitar que expire sin ser detectado a tiempo.

Fundamentos de redes

RA1.14Conexión con sistemas remotos SSH, FTP, SFTP

Conexión con sistemas remotos SSH, FTP, SFTP

Conectarse a sistemas remotos mediante SSH, FTP o SFTP permite administrar un servidor sin acceso físico a él, cada protocolo con distintas garantías de seguridad y funcionalidad. SSH ofrece una conexión cifrada de línea de comandos ideal para tareas de administración avanzada, mientras que SFTP añade transferencia segura de archivos sobre el mismo canal cifrado. El protocolo FTP tradicional, al no cifrar la información transmitida, se considera hoy una opción insegura salvo en entornos muy controlados. Elegir el protocolo adecuado según la tarea y priorizar siempre las variantes cifradas reduce significativamente el riesgo de exposición de credenciales.

Un administrador reemplaza las conexiones FTP tradicionales del equipo por SFTP para cifrar tanto las credenciales como los archivos transferidos.

El protocolo SSH fue creado en 1995 como respuesta directa a las vulnerabilidades de seguridad de sus predecesores no cifrados.

RA2.01Posicionamiento de páginas web (SEO)

Posicionamiento de páginas web (SEO)

El posicionamiento de páginas web, o SEO, es el conjunto de técnicas orientadas a mejorar la visibilidad de un sitio en los resultados orgánicos de los motores de búsqueda. Combina factores técnicos, como la estructura y velocidad del sitio, con factores de contenido, como la relevancia frente a la intención de búsqueda del usuario. Un buen posicionamiento no depende de una sola acción aislada, sino de la consistencia entre múltiples prácticas aplicadas a lo largo del tiempo. Los resultados del SEO suelen consolidarse de forma gradual, a diferencia de la publicidad pagada, que ofrece visibilidad inmediata pero temporal.

Un sitio reestructura sus encabezados y mejora sus tiempos de carga antes de notar un incremento sostenido en su posición dentro de los resultados de búsqueda.

Los algoritmos de los principales motores de búsqueda se actualizan cientos de veces al año, aunque la mayoría de esos cambios pasan inadvertidos para la mayoría de los sitios.

Ignorar cualquiera de estos fundamentos limita el impacto de los esfuerzos invertidos en los demás. RA3.01Pruebas y verificación de páginas Web en navegadores y dispositivos móviles

Pruebas y verificación de páginas Web en navegadores y dispositivos móviles

Probar y verificar una página web en distintos navegadores y dispositivos móviles asegura que la experiencia del usuario se mantenga consistente sin importar cómo acceda al sitio. Cada navegador interpreta ciertos elementos de código con pequeñas diferencias, lo que puede provocar fallas visuales o funcionales que pasan desapercibidas si solo se prueba en un entorno. Las pruebas en dispositivos móviles son especialmente críticas, dado que la mayoría del tráfico web actual proviene de pantallas pequeñas con capacidades técnicas distintas al escritorio. Omitir esta etapa de verificación puede hacer que una parte significativa de la audiencia experimente el sitio de forma deficiente sin que el equipo lo detecte.

Antes de publicar un rediseño, un equipo revisa el sitio en los navegadores y tamaños de pantalla más utilizados por su audiencia real.

El tráfico web desde dispositivos móviles superó al tráfico desde computadoras de escritorio a nivel global desde mediados de la década de dos mil diez.

RA3.02Técnicas de verificación

Técnicas de verificación

Las técnicas de verificación incluyen pruebas manuales, pruebas automatizadas y revisiones de accesibilidad que en conjunto detectan errores funcionales, visuales y de usabilidad antes de que el usuario final los encuentre. Las pruebas automatizadas permiten repetir verificaciones extensas de forma rápida cada vez que se actualiza el sitio, mientras que las pruebas manuales siguen siendo valiosas para detectar problemas de experiencia difíciles de programar. Combinar ambos enfoques ofrece una cobertura más completa que depender de uno solo. Documentar los casos de prueba utilizados facilita repetir la verificación de forma consistente en cada nueva versión del sitio.

Un equipo automatiza la verificación de enlaces rotos, pero revisa manualmente la experiencia de navegación completa antes de cada lanzamiento importante.

Las pruebas automatizadas pueden ejecutarse en cuestión de minutos, cubriendo escenarios que manualmente tomarían horas de revisión repetitiva.

RA3.03Herramientas de depuración para distintos navegadores

Herramientas de depuración para distintos navegadores

Las herramientas de depuración integradas en los navegadores permiten inspeccionar el código, monitorear el rendimiento y diagnosticar errores directamente mientras se navega por el sitio en desarrollo. Estas herramientas muestran información como el tiempo de carga de cada recurso, errores de ejecución de scripts y la estructura real del documento renderizado en pantalla. Aprender a interpretar correctamente esta información acelera significativamente la resolución de problemas frente a intentar corregir código a base de prueba y error. Cada navegador ofrece herramientas de depuración con particularidades propias, por lo que conviene familiarizarse con más de una.

Un desarrollador utiliza las herramientas de depuración del navegador para identificar por qué un script no se ejecuta correctamente en producción.

Las herramientas de desarrollo integradas en los navegadores modernos permiten simular distintos tamaños de pantalla sin necesidad de dispositivos físicos adicionales.

RA3.04Navegadores: tipos y plug-ins

Navegadores: tipos y plug-ins

Existen distintos tipos de navegadores, cada uno con su propio motor de renderizado, lo que explica por qué una misma página puede verse o comportarse de forma ligeramente distinta entre ellos. Los plug-ins o extensiones amplían la funcionalidad de un navegador, pero también pueden interferir con el comportamiento normal de un sitio si no se consideran durante las pruebas. Conocer los navegadores más utilizados por la audiencia objetivo permite priorizar las pruebas en los entornos que realmente importan. Mantenerse al tanto de actualizaciones importantes en motores de renderizado ayuda a anticipar cambios que podrían afectar la compatibilidad del sitio.

Un equipo revisa las estadísticas de su audiencia para priorizar las pruebas de compatibilidad en los dos navegadores más utilizados por sus visitantes.

Los distintos motores de renderizado de los navegadores pueden interpretar de forma diferente el mismo código, lo que explica variaciones visuales entre ellos.
